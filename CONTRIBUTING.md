# Як пропонувати зміни

Дякую, що допомагаєш з підручником. Сайт збирається з гілки `main` (GitHub Pages) — тому в `main` напряму не пушимо.

## Короткі правила

1. Зроби гілку від актуального `main` (наприклад `fix/det2-focus` або `docs/typo`).
2. Міняй лише те, що стосується задачі. Не переписуй сусідні сторінки «заодно».
3. Перед PR відкрий сторінку локально і перевір інтерактив (кліки, формули, введення чисел).
4. У PR напиши 2–3 речення: **що** змінилось і **навіщо**.
5. Дочекайся review — merge робить maintainer після перегляду.

## Локально

Файли — звичайний HTML. Достатньо відкрити папку через локальний сервер, наприклад:

```bash
python3 -m http.server 8877
```

Далі: `http://127.0.0.1:8877/`

## Чого уникати

- Force-push і переписування історії на `main`
- Великі PR «на все відразу» — краще кілька маленьких
- Ламати позначення й знаки в поясненнях заради коротшого тексту

Питання й ідеї — через Issues.
